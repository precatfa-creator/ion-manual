**User** حساب الدخول، و**Role** مجموعة حقوق قد يحمل المستخدم أكثر من واحدة منها. يربط **Employee** الحساب بالموظف ومديره وقسمه، وهذا الربط ضروري للطلبات الذاتية ولعدد من شروط الموافقة.

## إعداد المستخدم للعمل

يتولى **System Manager** إنشاء الحساب وتحديد أدواره. يراجع فريق الموارد البشرية رابط User ID على Employee، والقسم والمدير المباشر. امنح الأدوار المطلوبة للمهمة فقط؛ لا تستخدم Select All كطريقة إعداد عادية.

| المهمة | الأدوار ذات الصلة |
| --- | --- |
| تقديم طلب مواد | Employee مع حساب مرتبط بموظف |
| مراجعة شراء المواد | Purchase Manager، ثم Accounts Manager، ثم Stock Manager حسب المرحلة |
| صرف المواد أو نقلها | Stock Manager للاعتماد |
| طلبات موظفي الإدارة الفنية | Technical Administration Staff يقيد الغرض إلى Material Issue؛ لا يعطي موافقة فنية |
| إدارة فرصة Dedicated / SM / Hotels / ISP / Tenders | مدير الحساب الموافق للمسار: Dedicated / SM / Hotels / ISP / Tenders Account Manager |
| تحديد نطاق الفرص | Sales Engineer |
| تنظيم المسح وإتمام مرحلته | Surveyor Manager |
| تنفيذ المسح | Surveyor، مع التعيين وصلاحية الحقول ذات الصلة |
| العمل على تذكرة Issue | Support Team |
| تحويل المخزون بين الشركات | Stock User أو Stock Manager أو System Manager، مع متطلبات القيود الناتجة |
| إدارة إعدادات العمولات وكشوفها | System Manager في مصفوفة الموقع الحالية |

راجع جداول كل DocType في فصله، فهي تبين **الإنشاء والقراءة والتعديل والاعتماد والإلغاء** بدلاً من افتراض أن المسمى الإداري يعطي كل الحقوق.

## أربعة أسباب لاختلاف ما يراه المستخدمون

1. **صلاحية DocType**: هل يحمل دوراً يقرأ أو يعدّل المستند؟
2. **نطاق السجلات**: هل المستند يخص شركته أو موظفه، أو أُسند إليه؟
3. **مستوى الحقل (Permission Level)**: بعض الأقسام تحتاج صلاحية مختلفة عن بقية المستند.
4. **سير العمل**: هل حالته تسمح بالإجراء، وهل تحقق شرطه؟

**Role Permission Manager** يعدّل مصفوفة الحقوق؛ **User Permission** يقيد نطاق البيانات بالقيم المرتبطة. شاشة Workflow تحدد دور كل انتقال، ولا تمنح حقوق DocType الناقصة تلقائياً.

## تعارضات يجب أن يعرفها المسؤول

- **Hotspot**: الانتقالات تستخدم Hotspot Sales وPre-Sales وSurveyor Manager، بينما صفوف صلاحيات DocType الحالية تمنح الوصول لـ System Manager وDedicated QA. قد لا يكفي دور الانتقال وحده لفتح السجل.
- **Late Entry Request**: Approve مرتبط بـ All، وReject بـ Report Manager. لا يوجد شرط مدير مباشر في هذين الانتقالين؛ لا تصفه كاعتماد حصري للمدير.
- **EXTRA HOURS REQUEST**: الانتقال يستخدم Employee بشرط أن يكون المستخدم هو المدير المباشر المرتبط بموظف الطلب؛ صلاحيات الموظف الأساسية مقيدة بالمستندات التي يملكها، فيجب التحقق من وصول المدير إلى طلب موظفه.
- **Sales Target and Commission Sheet**: الانتقالات باسم All، لكن مصفوفة المستند تقصر الوصول على System Manager. بعض انتقالات الإلغاء لا تقابلها صلاحية Cancel لهذا الدور.

هذه فروق في الإعداد الحالي، وليست تعليمات لمنح صلاحيات إضافية تلقائياً. تم توثيقها دون تعديل النظام.

## لغة الواجهة

لغة User تتحكم بترجمة الواجهة. الصور الجديدة توثق الواجهة الإنجليزية التي ظهرت وقت المراجعة، ويشرح النص العربي وظيفة الحقول. لا تفترض أن تبديل اللغة يغيّر الدور أو خطوات الموافقة.
